# Phase 5 implementation

## Request and content policy

The Next.js Metadata API owns canonical, search and social tags. Canonicals use `https://saltedfocaccia.com` and the route path without tracking, size or session parameters. Next serializes the bare origin for the home metadata and the sitemap includes the equivalent URL with its root slash. The preferred hostname redirects www permanently. The deployment origin in `NEXT_PUBLIC_SITE_URL` continues to govern commerce. Missing content uses the existing 404 behavior without inheriting a home canonical. The Next 16.4.6 HTML-limited crawler defaults are extended for Googlebot, OAI-SearchBot and PerplexityBot so those agents receive metadata in the head. Bingbot and major social preview agents were already included.

Search title and description prioritize the page’s published override. Dynamic pages derive titles from the display name and published category. Static editorial routes have descriptive route-specific fallbacks. Published descriptions precede generated summaries and global defaults. Internal Studio names are never used. The brand suffix is added once. Social fields can use page overrides, and images fall back from the approved page share asset to its editorial photo, the default Site Settings share asset and a 1200 × 630 Salted artwork card. The fallback artwork uses the existing wordmark and published hero copy. Known placeholder and decorative images are excluded from social and structured-data imagery. Titles, descriptions, paths, image alt and entity values use stega-cleaned text.

Sanity Studio extends **Search & social** with title/description guidance, social overrides, image alt and a page hide option. Site Settings uses the existing business name, public contact email and Instagram field, and adds a **Public business details for search** group for factual description, telephone, pickup geography, approved public street, social profiles and logo. The Site Settings hide toggle applies globally. The product field **Keep this unavailable product in search** preserves useful temporary product pages when approved. The recipe search approval field governs Recipe markup. Existing editorial content, published overrides and live preview remain intact.

Indexable public pages require the apex hostname, a production-mode non-preview environment, the explicit server flag, a published eligible document and no hide switch. Draft Mode emits noindex and omits schema, while normal SEO calculations explicitly read the published Sanity perspective. Staging and preview hosts get a site-wide `X-Robots-Tag`. Private, Studio, order, utility and API routes get noindex even after launch. The app’s noindex headers and directives complement any separately configured Vercel protection.

The app returns robots.txt and a sitemap using Next metadata routes. Robots excludes Studio, API and order crawls while allowing public pages, storefront resources and share-image downloads. On staging and before approval, robots omits the sitemap reference and XML contains no URLs. The approved apex serves canonical URLs from current published content. Fixed pages and dynamic detail paths share eligibility logic with metadata. Sanity revision time supplies `lastmod`; sitemap generation reads published content on request. Studio is served from its original separate root. Order success uses a separate root with the same shell and cart, omitting GA so automatic page views cannot collect a Checkout session query.

## Structured data and discoverability

- The homepage emits Organization, WebSite and WebPage entities with stable canonical IDs, the Salted identity, the published Rocklin pickup context, official Instagram and the public email from Site Settings. Bakery is emitted only when an approved street address is configured and already publicly visible on Pickup. Pickup windows, coordinates, price ranges, testimonials and ratings are omitted from the business graph. [LocalBusiness requirements](https://developers.google.com/search/docs/appearance/structured-data/local-business) · [Schema.org Bakery](https://schema.org/Bakery)
- Product detail uses Product for a single size and ProductGroup for selectable sizes. A `?size=<variant-id>` URL preselects the size and renders its existing image, price and controls. The base detail remains the canonical. Offers use USD integer-cent source amounts compared against the fresh published checkout catalog. An offer is emitted only when the shared storefront schedule confirms a future, orderable Friday after blackout and cutoff checks and the variant exists in the purchasable catalog. No offer is emitted for missing schedule data, a stale price, disabled sizes or unavailable products. Placeholder-only products may lack the images required for Google shopping appearances. Pickup-only products make no shipping claims. [Google product markup](https://developers.google.com/search/docs/appearance/structured-data/product) · [Google variant guidance](https://developers.google.com/search/docs/appearance/structured-data/product-variants/)
- Recipe markup uses published, reviewed content with an image, ingredients and instruction bodies. Optional author, date published, category, cuisine, servings and ISO durations come from editor fields. Serving ideas can use WebPage and breadcrumbs without Recipe. The published dataset tested had no active recipe details. [Google Recipe requirements](https://developers.google.com/search/docs/appearance/structured-data/recipe)
- WebPage, AboutPage and CollectionPage identify the relevant page type. Breadcrumbs link to real route hierarchies. The storefront and recipe card links use anchors. Related products and recipes retain their CMS relationships. Product details now render the existing storage and pickup links when their CMS labels are populated. The hero wordmark is an H1 with an accessible business name. The rollout relies on first-party, visible answers and standard crawler support. [Search Essentials](https://developers.google.com/search/docs/essentials) · [SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) · [Google AI search guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

Public pages and assets use the wildcard robots rules, including for Googlebot, Bingbot, OAI-SearchBot and PerplexityBot. The sample staged requests from OpenAI and Perplexity user agents returned 200. Those checks exercise application delivery and agent matching. Platform WAF, source IP verification, real crawl and actual search inclusion require post-deploy review. The existing Squarespace domain sends a blanket crawl block during its coming-soon period. The new apex rules preserve the existing named restrictions for content collection, including GPTBot, Google-Extended, ClaudeBot, Applebot-Extended and CCBot, while allowing discovery crawlers to fetch public pages. Keep any change to those content-use restrictions for an explicit business decision. `llms.txt` remains experimental and adds no verified ranking benefit for this site, so the published pages and XML sitemap are the supported discovery sources. [OpenAI search and training crawlers](https://developers.openai.com/api/docs/bots) · [Perplexity crawlers](https://docs.perplexity.ai/docs/resources/perplexity-crawlers) · [Google crawling controls](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers#google-extended)

## Verification

- Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. The SEO tests cover noindex eligibility, canonical construction, escaped JSON-LD, stega stripping, product offer freshness and fixture-based Recipe fields.
- Point Playwright at a local production build using `PLAYWRIGHT_BASE_URL=http://localhost:3000 npm run test:e2e -- seo.spec.ts`. To exercise the apex launch path locally, set `SEO_INDEXING_ENABLED=true` for both build and server, plus `SEO_E2E_LAUNCH_APPROVED=true` for the test runner. Tests pass synthetic Host headers to the loopback server and use the ordinary local hostname for browser navigation. Read-only published Sanity content supplies the test catalog.
- The launch simulation produced 14 canonical sitemap URLs with revision timestamps. It excluded Studio, order and preference routes, inactive pesto and unpublished recipes. The branded image returned a 1200 × 630 PNG locally. External rich-result validation, hosted platform policy and Search Console/field measurements are pending launch.

The final launch-enabled loopback browser run passed all five SEO cases, including every sitemap URL, crawler head metadata, selected-size price parity, correct 404s, crawler restrictions, and the Draft Mode comparison. The nonmutating storefront run passed nine browser cases, including cart quantities, size images and controls, pickup calendar, intercepted checkout, unverified confirmation and mocked special-order submission. Unit tests passed 135 cases. Lint reported one existing unused helper warning in the cart drawer, with no errors. See the [audit measurements](seo-audit.md#after-implementation) for mobile lab and axe results.

Production payment activation, hosted crawler behavior and external rich-result reports require separate launch verification. No paid Stripe browser test, webhook delivery, or email send was performed in Phase 5.
